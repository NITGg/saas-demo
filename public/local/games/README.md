## بنك الكلمات

> ⚠️ **لم يعد هذا هو المصدر.** الجداول في ملفات اللغة صارت **المحتوى الأوّل
> فقط**: تُنسَخ مرّة واحدة عند التثبيت إلى صفوف تخصّ كلّ لعبة، وما تقرؤه الألعاب
> بعد ذلك هو `local_games_content` وحده. التفاصيل في قسم
> [التحكّم في الألعاب](#التحكّم-في-الألعاب-game-control) أدناه.
>
> تحرير هذه الجداول لا يغيّر ما يلعبه الأطفال، وإنّما يغيّر ما يستعيده زرّ
> «استعادة المحتوى المرفق».

المفتاح `wordbank` في `lang/<lang>/local_games.php`، سطر لكلّ كلمة بالشكل
`كلمة|إيموجي|تعريف`، ورفّ المتجر في `shopitems` بالشكل `إيموجي|اسم`.

> ⚠️ الكلمات بدون تشكيل عمداً: ألعاب الحروف تقسّم الكلمة إلى مربّعات، وعلامة
> التشكيل كانت ستصير مربّعاً مستقلاً.
## البنية

```
index.php              صفحة الركن — كل الألعاب في شبكة كروت
play.php               صدفة اللعب المشتركة لكل الألعاب
classes/registry.php   سجل الألعاب الـ24 + شروط الشارات
classes/progress.php   النقاط والشارات (منطق الأعمال)
classes/external/      الدالة التي يستدعيها المتصفح آخر كل جولة
js/shell.js            الصدفة: الصوت، الـHUD، البداية والنهاية، الحفظ
js/<slug>.js           لعبة واحدة لكل ملف
templates/             hub.mustache و play.mustache
styles.css             تصميم الركن كله
```

القاعدة: **`shell.js` يملك كل ما يجب أن يتصرّف بنفس الطريقة في الـ24 لعبة** —
الصوت، النقاط، كارت النهاية، الحفظ. ملف اللعبة يصف جولته فقط.

## إضافة لعبة جديدة

مثال: اللعبة 03 `math-shop`.

**1.** في [`classes/registry.php`](classes/registry.php) غيّر حالتها إلى
`STATUS_LIVE` وأضف شاراتها:

```php
'math-shop' => [
    'num' => 3, 'emoji' => '💰', 'category' => 'numbers',
    'level' => 2, 'status' => self::STATUS_LIVE,
    'badges' => ['smart-shopper' => ['correct' => 15, 'maxwrong' => 1]],
],
```

**2.** أضف في ملفَّي اللغة (`lang/en` و `lang/ar`):

```php
$string['js_math_shop_ready'] = '...';   // عنوان كارت البداية
$string['js_math_shop_howto'] = '...';   // شرح مختصر
$string['badge_smart_shopper'] = '...';
$string['badgehint_smart_shopper'] = '...';
```

> اسم المفتاح = الـslug بشرطة سفلية بدل الشرطة. `play.php` يبني
> `js_<key>_ready` و `js_<key>_howto` تلقائياً، فالتسمية إلزامية.
> أي مفتاح يبدأ بـ `js_` يصل إلى المتصفح تلقائياً في `api.strings`
> (بدون البادئة).

**3.** أنشئ `js/math-shop.js`:

```js
window.LocalGames.register('math-shop', function (api) {
    return {
        start: function () { /* ابنِ الجولة داخل api.stage */ },
        stop:  function () { /* أوقف أي مؤقت أو حلقة رسم */ }
    };
});
```

**4.** أضف تنسيقاتها في [`styles.css`](styles.css) تحت `.gc-shop`.

**5.** ارفع `version.php` **فقط لو** أضفت جداول أو صلاحيات، ثم:

```bash
docker compose exec moodle php admin/cli/purge_caches.php
```

لا شيء آخر — الكارت يظهر في الركن وحده.

### ⚠️ بعد أي تعديل في `styles.css`

Moodle يدمج `styles.css` الخاص بكل إضافة داخل **ستايل الثيم المُجمَّع**
(لذلك لا يوجد `$PAGE->requires->css()` في `index.php` أو `play.php` — سيكون
تحميلاً مكرراً). النتيجة أن `purge_caches.php` وحده لا يكفي:

```bash
docker compose exec moodle php admin/cli/purge_caches.php
docker compose exec moodle php admin/cli/build_theme_css.php --themes=nit
```

**الترتيب مهم.** `purge_caches` بعد `build_theme_css` يبطل الملف المبني
ويعيدك لنسخة قديمة — أهدرتُ وقتاً في تشخيص «تعديل لم يُطبَّق» وسببه هذا فقط.
دائماً: امسح ثم ابنِ، ولا تمسح بعدها.

### ⚠️ الخصائص التي يقلبها rtlcss

Moodle يمرّر CSS عبر **rtlcss** في اللغات العربية، فيقلب كل خاصية *فيزيائية*
حتى لو كانت نيّتك خلاف ذلك. وقعنا في هذا مرتين:

| الخاصية | ما حدث | الحل |
|---------|--------|------|
| `direction: ltr` على لوحة التحكّم | انقلبت إلى `rtl` فصار زر «شمال» يمين الشاشة | `/* rtl:ignore */` قبل السطر |
| `transform-origin: 0 50%` لشريط التحديد | صارت `100% 50%` فدار الشريط خارج الشبكة | تُضبط من JS — الأنماط السطرية لا يمسّها rtlcss |

القاعدة: لو كان الشيء **تخطيطاً** فاستخدم الخصائص المنطقية ودع rtlcss يعمل؛
ولو كان **جهاز تحكّم أو هندسة محسوبة** فامنعه صراحةً.

## ما تحصل عليه اللعبة من `api`

| العضو | الاستخدام |
|-------|-----------|
| `api.stage` | العنصر الذي تبني اللعبة داخله |
| `api.strings` | كل مفاتيح `js_*` باللغة الحالية |
| `api.fmt(n)` | الرقم بالأرقام العربية الهندية في الواجهة العربية |
| `api.random(a,b)` · `api.pick(arr)` · `api.shuffle(arr)` | مساعدات |
| `api.say(text)` | قراءة النص بصوت عالٍ |
| `api.wordlist` | مفردات أوسع للتحقق فقط (بلا صور ولا تعريفات) |
| `api.correct(msg, points)` | تسجيل إجابة + صوت + رسالة عائمة. `points` اختياري (افتراضي 1) |
| `api.wrong(msg)` | إجابة غلط — الرسالة تبقى ٢.٥ ثانية حتى يلحق الطفل يقراها |
| `api.setLives(n)` | إظهار المحاولات كقلوب |
| `api.setProgress(done, total)` | **إلزامي** — يظهر «٣ / ٥» في الشريط |
| `api.finish(score)` | إنهاء الجولة، الحفظ، وكارت النهاية |

> ⚠️ **`setProgress` ليست اختيارية.** لعبة بلا مؤشّر تقدّم تبدو للطفل بلا نهاية،
> فلا يعرف إن كان توقّفه الآن يضيّع شيئاً. نادِها عند كل زيادة، **لا عند الرسم
> فقط** — وإلا وقف العدّاد عند «١٤ / ١٥» في آخر خطوة.

> ⚠️ `correct` تعدّ **الأحداث** (وعليها تُبنى الشارات) و`score` تعدّ **النقاط**.
> هما نفس الرقم في كل لعبة تعطي نقطة لكل إجابة، ويفترقان في «كوّن الكلمة».

## قواعد ملزِمة (من مستند التصميم)

مذكورة في `docs/Games Doc/README.md` قسم "قواعد كل لعبة". أهمها في الكود:

- **الغلط مش عقاب** — لا رسالة قاسية ولا نسبة مئوية. في `math-race` انتهاء
  الوقت يعيد المسألة للطابور ولا يُنقص شيئاً.
- **محاولات غير محدودة** — "العب تاني" حاضر دائماً في كارت النهاية.
- **صوت مع كل نص** — كل سؤال وكل قاعدة تُقرأ عبر `api.say()`.
- **أزرار كبيرة** — لمس الأصابع الصغيرة، لذلك `.gc-answer` و `.gc-steer`
  بارتفاعات كبيرة.

## المحتوى الأوّل في ملفات اللغة

هذه الجداول هي ما يُزرَع منه محتوى كلّ لعبة أوّل مرّة، وما يستعيده زرّ «استعادة
المحتوى المرفق». **ليست ما تقرؤه الألعاب** — الألعاب تقرأ صفوفها الخاصّة في
`local_games_content`.

| المفتاح | الصيغة | يُزرَع منه |
|---------|--------|-----------|
| `wordbank` | `كلمة\|إيموجي\|تعريف` | ٨ ألعاب حروف وذاكرة، لكلٍّ نسختها |
| `wordlist` | كلمات مفصولة بمسافات | كوّن الكلمة |
| `quizbank` | `موضوع\|سؤال\|صح\|غلط\|غلط\|غلط` | ٦ ألعاب أسئلة، لكلٍّ نسختها |
| `tfbank` | `جملة\|1أو0\|السبب` | صح ولا غلط |
| `whoami` | `إجابة\|إيموجي\|تلميح×٣` | مين أنا؟ |
| `colourbank` | `اسم\|hex` | تحدي الألوان |
| `shopitems` | `إيموجي\|اسم` | متجر الحساب |

أمّا سباق الحساب وصياد الأرقام وفرقعة البالونات فمحتواها الأوّل مكتوب في
`classes/admin/defaults.php` لا في ملفّ لغة، لأنّه قواعد توليد لا نصوص.

المواضيع الأربعة (`math` · `science` · `language` · `animals`) هي أقسام العجلة في
اللعبة ١٥، وهي الآن حقل `topic` في محتوى العجلة وحدها.
## الشارات

الشرط يُقيَّم **على الخادم** في `progress::submit()`، لا في المتصفح.

| المفتاح | معناه |
|---------|-------|
| `streak` | أطول سلسلة إجابات صح |
| `correct` | عدد الإجابات الصح |
| `maxwrong` | أقصى غلط مسموح |
| `goal` | **هدف اللعبة نفسها** |

`goal` هو ما ترسله اللعبة عبر `api.finish(score, goal)`، ومعناه يختلف بحسبها:
جولات XO المكسوبة، الوصول لآخر كوكب، لوحة ذاكرة داخل ميزانية القلبات، مرحلة
جري بلا فقد قلب. عدّ الإجابات الصح لا يعبّر عن أيٍّ من هذه، واختراع قاعدة لكل
لعبة كان سيضع منطق اللعب داخل الخادم.

تُمنح الشارة مرة واحدة مدى الحياة.


## التحكّم في الألعاب (Game control)

*إدارة الموقع ← الإضافات ← الإضافات المحلية ← **التحكّم في الألعاب***

كل ما فوق يصف الركن **كما يُشحن**: الكتالوج في `registry.php`، والمادة الأولى في
ملفات اللغة. أمّا ما يلعبه الأطفال فعلياً فهو ما في قاعدة البيانات، ومن هذه
الشاشة يُدار.

### المحتوى مملوك للعبة، لا مشترك بينها

`local_games_content` فيه **صفّ واحد للعبة واحدة**. الألعاب الخمس التي تسأل سؤالاً
وتعرض إجاباته تتشابه في *شكل* الصفّ، ولا تشترك في صفٍّ واحد: فتعديل أسئلة «رحلة
الفضاء» لا يمسّ «XO التعليمي» بحال.

هذا تغيير مقصود عن التصميم الأول، الذي كان يجعل `quizbank` بنكاً واحداً تقرؤه ستّ
ألعاب. البنك المشترك لا يمكن تحريره بأمان: من يحرّره لا يرى من يقرؤه غيره، فتتغيّر
ألعاب لم يكن يقصدها.

| الجدول | يحمل |
|--------|------|
| `local_games_game` | بطاقة اللعبة: الاسم والوصف والتفعيل والمستوى والترتيب |
| `local_games_content` | صفوف محتوى اللعبة، كلٌّ منها JSON بمفاتيح شكلها |

### شكل المحتوى لكلّ لعبة

لكلّ لعبة شكل واحد يُعرَّف في `registry::shapes()` ويُربَط بها في
`registry::shape_for()`. **لا توجد لعبة بلا محتوى قابل للتحرير.**

| الشكل | الحقول | الألعاب |
|-------|--------|---------|
| `questions` | سؤال، إجابة، ٣ إجابات خاطئة | معلومات عامة، XO، اختار الإجابة، رحلة الفضاء، الجري |
| `topicquestions` | ما سبق + الموضوع | عجلة الأسئلة |
| `words` | كلمة، صورة، تعريف | ٨ ألعاب حروف وذاكرة |
| `vocabulary` | كلمة | كوّن الكلمة |
| `statements` | عبارة، صحّتها، التفسير | صح ولا غلط |
| `clues` | إجابة، صورة، ٣ تلميحات | مين أنا؟ |
| `colours` | اسم اللون، القيمة الستّ عشرية | تحدي الألوان |
| `shopitems` | صورة، اسم | متجر الحساب |
| `sumrules` | العملية، مدى العددين | سباق الحساب |
| `numberrules` | نوع القاعدة، مدى عددها | صياد الأرقام، فرقعة البالونات |

### الألعاب الثلاث التي تولّد مادّتها

سباق الحساب وصياد الأرقام وفرقعة البالونات تخترع أسئلتها أثناء اللعب. تحويلها إلى
قوائم ثابتة كان يجعلها محدودة ومكرّرة، فما يحرّره المشرف هو **الوصفة** لا النتيجة:

- `sumrules`: كلّ صفّ عملية ومدى كلّ عدد من عدديها. حذف صفّ الضرب يمنع الضرب.
- `numberrules`: كلّ صفّ قاعدة (زوجي، فردي، أكبر من، أصغر من، يقبل القسمة، يساوي)
  ومدى العدد المستعمل فيها.

الشِّفرة المشتركة في `shell.js`: `api.sum()` و`api.numberRule(prefix)`. اللعبة
تظلّ تولّد بلا نهاية، لكن داخل ما أُعطي لها. ولو لم يبقَ صفّ واحد أنهت اللعبة
الجولة بهدوء بدل شاشة فارغة.

### اللغات: لا مبدّل لغة، ولا حقول مكرّرة

القيمة المترجَمة **قيمة واحدة** تحمل ترميز `{mlang}`، تماماً كاسم أيّ مقرَّر في
الموقع. و`local_nit_mlang` هو الذي يرسم فوق الحقل مُدخَلاً لكلّ لغة مثبَّتة ويؤلّف
الترميز عند الحفظ — فلا حاجة إلى مبدّل لغة في هذه الشاشة، ولا إلى صفّ لكلّ لغة.

الحقول المترجَمة تُرسَل باسم `gametext[...]`، وهذه البادئة مسجَّلة في
`local_nit_mlang\registry::TEXT_FIELDS`. أمّا `topic` و`hex` والأعداد فأسماؤها
مجرّدة لأنّها مفاتيح وأرقام لا تُترجَم.

> ⚠️ `$CFG->stringfilters` فارغ في هذا الموقع، أي أنّ `format_string()` **لا**
> يفكّ ترميز `{mlang}`. لذلك يفكّه `local_games\mlang::display()` في الشِّفرة، كما
> يفعل `local_jobform` و`local_nit_subscriptions` للسبب نفسه.

> ⚠️ لا تستعمل `empty()` للتحقّق من وجود قيمة مترجَمة: إجابة «٠» قيمة صحيحة
> (درجة تجمّد الماء أحد أسئلة الركن)، و`empty("0")` تساوي `true` فتُسقِط السؤال
> كلّه. المقارنة الصحيحة `!== ''`.

### المُدخَلات ليست ترجمة بعضها

بنك الكلمات الإنجليزي يعلّم الهجاء الإنجليزي، والعربي يعلّم العربي، وليسا قائمتين
متقابلتين. لذلك يُوسَم الصفّ الذي كُتب بلغة واحدة بتلك اللغة وحدها، ويختفي في
اللغة الأخرى بدل أن يُعرَض على طفل بلغة لا يلعب بها. وهذا ما تفعله
`mlang::has_language()` في `content::for_game()`.

وعند الزرع الأوّلي تُربَط اللغتان بمفتاح مستقلّ عن اللغة حيثما وُجد: الصورة في بنك
الكلمات ورفّ المتجر، والقيمة الستّ عشرية في الألوان. أمّا الأسئلة والعبارات
والتلميحات فقوائم متقابلة تُربَط بالترتيب.

```
db/install.php                      زرع المحتوى عند التثبيت
db/caches.php                       كاش `overrides` للبطاقات
```

### حدث نهاية الجولة

`shell.js` يطلق `local-games:roundfinished` على `.gc-play` (bubbles) عند انتهاء
الجولة، حاملاً `{gameid, correct, wrong, streak, score, goal}`، ويُطلَق **قبل**
اكتمال الحفظ عمداً: أيّ مضيف يمسك دفاتره الخاصّة — نشاط `mod_games` اليوم — لا
ينتظر شبكة الركن، والحدث يحمل الأرقام نفسها لا وعداً بها.

## نشاط اللعبة (mod_games)

إضافة مستقلّة تحت [`mod/games`](../../mod/games) تضع **لعبة واحدة من الركن داخل
مقرَّر**. ليست نسخة ثانية من الركن: تعرض القالب `local_games/play` نفسه وتحمّل
`shell.js` وملفّ اللعبة نفسيهما، وتُغذّى بمحتوى اللعبة نفسه.

ما يضيفه النشاط هو نصف الصورة الخاصّ بالمقرَّر: `games_play` يسجّل جولات الطالب
**في وحدة المقرَّر هذه**، وعليه يقوم تقرير «مَن لعب» وشرطا الإكمال. أمّا نقاط
الطفل وشاراته فتبقى للركن وتُحفَظ سواء لعب من الهَب أو من مقرَّر.
